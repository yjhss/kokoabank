# Database Architecture — 금융 데이터베이스 설계

## 1. 도입 배경

KokoaBank는 사용자 계좌와 이체 거래를 처리하는 인터넷은행 데모 서비스이다. 잔액과 거래내역의 정확한 관리, 데이터 무결성 및 동시성 제어를 고려하여 관계형 데이터베이스를 선택하였다.

## 2. PostgreSQL 선정 이유

- ACID 트랜잭션 지원
- 외래 키, UNIQUE, CHECK 제약조건을 통한 데이터 무결성 보장
- 행 단위 잠금 및 트랜잭션 격리 수준 활용
- Spring Data JPA 및 Flyway 연동
- AWS RDS for PostgreSQL 기반 운영환경으로 확장 가능

## 3. 데이터 모델

주요 테이블은 users, accounts, transfers, transactions로 구성한다.

- users: 사용자 정보 및 인증 데이터
- accounts: 사용자 계좌, 계좌번호, 잔액
- transfers: 이체 요청, 상태, 멱등성 키
- transactions: 계좌별 입출금 이력 및 거래 후 잔액

## 4. 설계 고려사항

### 금액 표현

원화 금액은 소수점 오차가 발생하지 않도록 BIGINT를 사용한다.

### 데이터 무결성

- 잔액은 0 이상
- 이체금액은 0 초과
- 출금 계좌와 입금 계좌는 서로 달라야 함
- 계좌번호와 멱등성 키는 중복 허용하지 않음
- FK를 통해 사용자·계좌·이체 간 참조 무결성 유지

### 인덱스

계좌 소유자 조회, 계좌별 거래내역 조회, 이체내역 조회를 고려하여 인덱스를 구성하였다.

## 5. Redis 활용 계획

Redis는 캐싱 및 보조 데이터를 관리하기 위한 용도로 사용한다. 금융 잔액과 거래 원장은 PostgreSQL을 기준으로 유지하며 Redis를 정합성의 최종 기준으로 사용하지 않는다.

## 7. 후속 작업

- 트랜잭션 원자성
- 동시 이체 및 Lost Update 방지
- 멱등성 키 기반 중복 처리 방지
- 거래 실패 시 Rollback
- 부하 테스트와 DB 성능 분석
